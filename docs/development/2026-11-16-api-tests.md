# GET APIテスト自動化 — 2026-11-16

## 目的
既存の公開GET APIを変更しても基本動作と安全性を維持できるよう、正常系・異常系のHTTPレベルの回帰テストを自動実行する。

## テスト構成
- **ランナー:** Node.js標準 `node:test`（`npm test`）
- **対象:** `tests/api.test.js`
- **モック:** MongoDBのコレクション操作をテスト用のメモリ内データで代替
- **検証方法:** Expressアプリをテスト用ランダムポートで起動し、実際にHTTPリクエストを送る
- **依存性注入:** `createApp` → `createApiRouter` → `createUserHandlers`
- **データベースの秘密情報:** 不要。CIにはMongoDBの接続URIを登録しない

## テストケース
| No | テスト内容 | 期待する結果 |
|---|---|---|
| 1 | GET /health | 200、サービス情報のJSON |
| 2 | GET / | 200、EJSドキュメントをHTMLで表示 |
| 3 | GET /api/users | 200、demo=trueのみ、公開4項目のみ、最大50件の指定 |
| 4 | GET /api/users?status=active | 200、activeのデモのみ |
| 5 | GET /api/users?status=inactive | 200、inactiveのデモのみ |
| 6 | GET /api/users/:id | 200、正しいObjectIdのレコード |
| 7 | 無効・重複したstatus | 400、DBへの問い合わせ前に拒否 |
| 8 | 不正なID形式 | 400、DBへの問い合わせ前に拒否 |
| 9 | 不存在ID／demo=false ID | 404、非公開データを返さない |
| 10 | DB未設定 | 503、設定情報を漏らさない |
| 11 | 想定外のDB障害 | 503、秘密情報をレスポンスに漏らさない |
| 12 | 一覧に50件を超えるデータ | 最大50件 |
| 13 | POST /api/users／不明API | 404、書き込みルートを提供しない |

## 自動実行

- `.github/workflows/api-tests.yml`
- `main` へのpushと、`main` 宛てPR、および手動起動で実行
- GitHub Actionsの `ubuntu-latest` / Node.js 22
- `npm install --ignore-scripts` → `npm test`
- ワークフロー権限は `contents: read` のみ
